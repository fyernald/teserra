# Changelog

All notable user-visible changes to Teserra are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Policy: [release process](docs/process/release-process.md#changelog-policy).

## [Unreleased]

### Added

- Positional sound and audio components (#313): voices with `PlayParams::spatial` are panned and attenuated linearly between `minDistance` and `maxDistance` around the listener (`AudioEngine::setListenerPosition()`, `setPosition()`, `setSpatial()`, `setDistances()`). `scene::AudioSource` plays a clip while its entity has it and `playing` is true, following the entity's position when `spatial`; `scene::AudioListener` marks the entity the player hears from. A scene stops its sources' voices when it exits or resets.
- Volume buses and audio in every App (#312): voices play into `audio::Bus::Music` or `Effects` (`PlayParams::bus`), which feed `Master`; `setBusVolume()` and `setBusMuted()` turn them down or off. The App owns the audio engine (`app.audio()`, `AppConfig::audio`), registers the clip loader and updates it every frame. Without a sound device it logs one warning and runs silently with the offline output; `--no-audio` turns sound off. Scene systems reach it as the `audio::Audio` resource. The debug UI's Stats window shows the voices in use.
- Sound files (#311): `audio::AudioClipLoader` loads `Asset<AudioClip>` from WAV and OGG Vorbis files (stb_vorbis), decoded into memory, or streamed (decoded while they play) when the sidecar says `{"stream": true}` (new `AssetImportSettings::stream`). `audio::registerAssetLoaders()` adds the loader with a silent fallback; `audio::decodeAudio()` and `AudioClip::stream()` work on bytes. Clips over `AudioDecodeConfig::maxDecodedBytes` (256 MiB) must be streamed.
- The audio module (#310): `teserra_audio` plays sound through miniaudio ([ADR-0027](docs/adr/0027-audio-miniaudio.md)). `audio::AudioEngine` mixes voices into the default sound device, or offline for `render()` (tests, machines without sound); `play(clip, {volume, pitch, pan, loop})` returns a `VoiceHandle` to stop or change the voice, and `update()` reclaims voices that ended. `audio::AudioClip::create()` makes mono or stereo clips from samples in code, at any sample rate. New `Audio` values of `LogCategory` and `Module`. The leak check keeps miniaudio inside `engine/audio/src/`.
- The debug UI's asset list and renderer stats (#301): an **Assets** window with every asset's path, type, state (loaded, fallback in yellow, failed in red) and handles, filtered by path or type, and a **Renderer** window with the frame's views, camera targets and scene target size, the sprite pass's sprites, batches, tilemap chunks, draw calls and material pipelines, the debug pass's lines, and the debug UI pass's numbers. New API: `assets::AssetRegistry::forEach()` with `AssetInfo` and `AssetState`, `AssetLoader::typeName()` (the engine's loaders name their types; a game's loader may), `renderer::Renderer::stats()` and `SpritePass::materialPipelineCount()`.
- The debug UI's entity list and inspector (#300): an **Entities** window with every scene (the active one first) and its entities, filtered by `index:generation` or component name, and an **Inspector** window with the selected entity's components and their fields, read-only (vectors, Euler angles of quaternions, color swatches, entity fields as buttons that select them). The selection clears when its entity or scene goes away. New API: `ecs::World::forEachComponent()`, `scene::SceneManager::forEach()`, `math::degrees()` and `math::eulerAngles()`; `scene::Collider` describes its fields.
- The debug UI's log console (#299): a **Log** window with the last 2000 messages logged from any thread since the App started, colored by level, with level, category and text filters, auto-scroll that stops when you scroll up, and Clear (`debugui::LogConsole`, `LogBuffer`, `LogFilter`; `App::logConsole()`).
- The App owns the debug UI (#298): the backtick key opens and closes it (`AppConfig::debugUi`, `--debug-ui`, `App::setDebugUiOpen()`), and the game sees neither that key nor input the debug UI uses. A **Stats** window shows FPS, a graph of the last 120 frame times, fixed steps, the active scene and its entity count, and the window and framebuffer sizes; `App::debugUi().addWindow()` adds a game's own windows, listed in a View menu (`examples/demo_game` adds one). While closed, frames run no ImGui. `renderer::Renderer::renderOverlays()` draws only the overlay passes, which is how the App draws the debug UI over frames of render callbacks too. `TESERRA_WITH_DEBUG_UI` is a public compile definition of `teserra_engine`. Every example's smoke run also runs with the debug UI open (`teserra_add_smoke_run()`).
- Debug UI input (#297): `DebugUi::processEvent()` feeds ImGui from engine `platform::Event`s (keys and modifiers through `debugui::imguiKey()`, mouse buttons, movement and wheel, typed text, focus), and `wantsMouse()` / `wantsKeyboard()` say when the debug UI uses that input.
- The debug UI module (#296): `teserra_debug_ui` with `debugui::DebugUi` (a Dear ImGui 1.92 context) and `debugui::ImGuiPass`, Teserra's ImGui renderer backend on the RHI: one indexed draw per ImGui command with its scissor, textures created and updated as ImGui asks, colors decoded for sRGB outputs. `TESERRA_WITH_DEBUG_UI` (ON by default) builds it with vcpkg's `imgui`; OFF builds no ImGui code. The game template lists `imgui`. `renderer::Renderer::addOverlayPass()` adds passes that draw into the output after the composite pass, unscaled by the scene target. The engine module moves to layer 7.
- Linux is a supported platform (#127, [ADR-0026](docs/adr/0026-linux-support-targets.md)): Ubuntu 24.04 and 26.04 LTS with GCC 14.3+ or Clang 18+, on X11 or Wayland, built and tested in CI on every pull request (#283). Build instructions in the getting-started guide and build-and-ci.md (#284).
- Linux OS services (#280): `NativeFileSystem::executableDirectory()` and `userDataDirectory()` on Linux, the second following the XDG Base Directory spec (`$XDG_DATA_HOME`, else `$HOME/.local/share`). Part of the Linux port (#127).
- The whole engine builds and passes its tests on Linux with GCC and Clang (#282), with the CI presets `ci-linux-gcc` and `ci-linux-clang` (warnings as errors, SPIR-V validation).
- Windows on Linux (#281): the GLFW backend runs on X11 and Wayland, with OpenGL 4.5 core contexts (GLX or EGL), and `NativeWindowHandle` reports `Kind::X11` or `Kind::Wayland` with the display. vcpkg's `glfw3` is built with its Wayland feature on Linux, in Teserra's and the game template's manifests.
- The tilemap example loads a map made in Tiled (#276): `assets/island.tmj` with an external tileset, `island.tsj`, drawn over the generated map; the sample for bringing Tiled maps in.

### Changed

- `OpenGlContext::getProcAddress()` no longer promises `nullptr` for a function that doesn't exist (#281): GLX returns an address for any name. Whether a function exists comes from the GL version and the extensions, as glad already decides.

### Fixed

- The sprite pass no longer allocates every frame on Linux (#282): it sorted tilemap chunks by layer with `std::stable_sort`, which allocates a buffer in libstdc++. It now uses an allocation-free sort that keeps the same order.

## [0.1.0] - 2026-11-26

The first public release: a 2D engine for C++ developers on Windows, consumed from a game's own CMake project ([getting started](docs/guides/getting-started.md)).

### Added

- Project documentation: architecture, ADRs, coding standards, pattern catalog, build/CI and testing strategy, development and release process.
- Contributor guide, Code of Conduct, security policy, issue and pull request templates.
- CMake build skeleton: `teserra_add_module()` with a configure-time layer check, per-compiler warning flags, `teserra_core` with `<teserra/core/config.hpp>`, `<teserra/core/types.hpp>` and a generated `<teserra/core/version.hpp>`, and the `teserra_hello` example.
- One-command build: `CMakePresets.json` (Windows MSVC/clang-cl, CI, prepared Linux presets) and vcpkg manifest mode with a pinned baseline (`cmake --workflow --preset windows-msvc-debug`).
- Catch2 v3 test integration: `teserra_add_test()` registers each test case with CTest; `teserra_core_tests`; JUnit report from the `ci-windows` test preset.
- GitHub Actions CI: `windows-msvc` job (build and tests with test annotations and a cached vcpkg) on every push to `main` and every pull request; CI badge in the README.
- `.clang-format` and `.clang-tidy` (naming rules of ADR-0021), `format` / `format-check` / `check` targets and the CI `checks` job.
- Logging facade `<teserra/core/log.hpp>`: `TESERRA_LOG_{TRACE,DEBUG,INFO,WARN,ERROR,CRITICAL}(category, format, args...)` with compile-time checked `std::format` strings and source locations, engine categories plus `log::registerCategory()` for games, a compile-time floor `TESERRA_LOG_LEVEL_MIN`, runtime levels per category, colored console and rotating file output (`log::configure()`), and `log::CallbackSink` to capture messages. spdlog is a private dependency of `teserra_core`.
- Profiling macros `<teserra/core/profile.hpp>` (`TESERRA_PROFILE_SCOPE`, `_FUNCTION`, `_FRAME_MARK`, `_ALLOC`, `_FREE`, `_THREAD_NAME`); no-ops until the Tracy integration.
- Test helpers `teserra_add_header_check()` (every public header compiles on its own and keeps spdlog/fmt private) and `teserra_add_compile_fail_test()`.
- Assertions `<teserra/core/assert.hpp>`: `TESERRA_ASSERT`, `TESERRA_VERIFY`, `TESERRA_UNREACHABLE` and `TESERRA_FATAL` with optional `std::format` messages. Failures are logged at Critical with the caller's location and flushed; the default handler breaks into an attached debugger and aborts, and `setAssertHandler()` replaces it. CMake option `TESERRA_ENABLE_ASSERTS` (`DEFAULT`: Debug and RelWithDebInfo, `ON`, `OFF`).
- `Result<T>` and `Error` (`<teserra/core/result.hpp>`): `Result<T>` aliases `tl::expected<T, Error>` (a public dependency of `teserra_core`); `Error` holds an `ErrorCode`, the `Module` that failed and a message, and formats as `"<message> (<module>, <code>)"`; `fail()` creates errors; `TESERRA_TRY` and `TESERRA_TRY_ASSIGN` propagate them. Discarding a `Result` is diagnosed. `log::configure()` now returns `Result<void>` and leaves logging a failure to the caller.
- Math `<teserra/core/math.hpp>` over glm (a public dependency of `teserra_core`): `Vec2/3/4`, `IVec2`, `UVec2`, `Mat3`, `Mat4`, `Quat`, `Color`, `Rect`, 3D `Aabb`, and `teserra::math` functions (`dot`, `cross`, `length`, `normalize`, `lerp`, `radians`, `perspective`, `orthographic`, `lookAt`, `inverse`, `angleAxis`, `toMat4`, box helpers). glm is configured once with `GLM_FORCE_DEPTH_ZERO_TO_ONE` and `GLM_FORCE_RADIANS`; projections are right-handed with depth `[0, 1]` and +Y up.
- Generational handles: `Handle<Tag>` (`<teserra/core/handle.hpp>`: 32-bit index + 32-bit generation behind accessors, null by default, distinct types per tag, comparable, hashable, formattable) and `HandlePool<T, Tag>` (`<teserra/core/handle_pool.hpp>`: slot array with per-slot generations, FIFO slot reuse, retirement at the maximum generation, asserting `get()`, `tryGet()` returning `nullptr` for stale handles, `forEach()` over live objects).
- `teserra_core_sandbox` example: logging in several categories, a recoverable `Result` error handled with a fallback, handles and math; `--assert` shows a failed `TESERRA_ASSERT` with file and line in Debug. It runs as a CTest smoke test that fails on Error-level output.
- Platform layer `teserra_platform` (layer 1) with a GLFW backend (`TESERRA_WINDOW_BACKEND`, PRIVATE GLFW 3.4): `platform::Platform::create()`, `Window` (sizes, content scale, `setSize`, `setTitle`, close and focus state, `NativeWindowHandle`), `OpenGlContext` for OpenGL 4.5 core contexts, and an `EventQueue` with `WindowResized`, `WindowCloseRequested` and `FocusChanged` events. Window functions assert they run on the main thread. The header checks also reject GLFW and `<windows.h>` in public headers.
- Keyboard and mouse input in `teserra_platform`: `platform::Key` (physical keys with US-layout names) and `MouseButton` with `keyName()` / `mouseButtonName()`; `KeyChanged`, `MouseButtonChanged`, `MouseMoved`, `MouseScrolled` and `TextEntered` events from the GLFW backend; and `platform::Input`, built from those events each frame, with `isDown` / `wasPressed` / `wasReleased` for keys and buttons, mouse position and delta, scroll, typed text (UTF-8) and `axis2D()`. Losing focus releases held keys and buttons.
- Timing in `teserra_platform`, using only `std::chrono`: `platform::Clock` (monotonic `now()` in nanoseconds) with `SteadyClock` and a `ManualClock` for tests; `Platform::clock()`; `FrameTimer` (delta, elapsed time, frame count, FPS averaged over 500 ms windows); and `FixedStepAccumulator` (fixed steps, default 60 Hz, with the remainder carried over and at most `maxStepsPerFrame` steps after a stall, reporting the dropped ones).
- `teserra_engine` (layer 6) with `engine::App`: owns the platform and the window (created in dependency order, destroyed in reverse), runs the frame (events and `Input`, fixed steps, update, present with vsync) with `AppCallbacks` until `quit(exitCode)`, a close request or `AppConfig::maxFrames`, and returns the exit code from `run()`. Initialization failures are logged and make `run()` return 1. The engine flags `--frames N` and `--hidden-window` are read from `AppConfig::args`. An injected `platform::Platform` lets tests run it headless.
- `teserra_window_input` example: logs keyboard, mouse and text input, shows FPS, the cursor and a WASD-moved position in the title, and quits on Escape or close; its CTest smoke run (`--frames 120 --hidden-window`) is skipped on machines without OpenGL 4.5.
- Shared test support for all test executables (`tests/support/`): failed assertions fail the current test instead of aborting, `REQUIRE_ASSERTS(expr)` / `teserra::test::requireAssert()`, `teserra::test::LogCapture`; `teserra_add_abort_test()` for behavior that ends the process.
- Layer and leak checks: `tools/scripts/check_layers.py` (a module includes only its own headers and those of its direct `DEPENDS`) and `tools/scripts/check_gl_leaks.py` (GL, Vulkan, GLFW, Win32 and glm names stay in their backend or module; `TODO(#issue)`), with unit tests, `layer-check` / `leak-check` targets in `check`, and steps with pull request annotations in the CI `checks` job.
- `teserra_rhi` (layer 2), the public RHI types: handles, `Format` / `VertexFormat` with `formatInfo()` / `vertexFormatInfo()`, API bounds (`kMaxColorAttachments`, ...) and `DeviceLimits`, the descriptors `BufferDesc`, `TextureDesc`, `SamplerDesc`, `ShaderModuleDesc`, `GraphicsPipelineDesc` (all fixed-function state) and `RenderPassDesc` (trivially copyable, load/store ops), the `Device` and `Swapchain` interfaces, and `createDevice()`, which picks among the backend factories the build passes in. No backend yet.
- `<teserra/core/flags.hpp>`: `TESERRA_FLAGS(Enum)` gives scoped flag enums `| & ^ ~`, compound assignment, `hasAll()` and `hasAny()`.
- `rhi::CommandList` (`<teserra/rhi/command_list.hpp>`): records render passes, bindings (pipeline, bind groups with dynamic offsets, vertex and index buffers), viewport and scissor, draws, buffer and texture copies, and debug groups as POD records in a reused byte stream, without backend calls or, after warm-up, heap allocations. Recording rules (no nested passes, draws need a pass and a pipeline, each pass starts with nothing bound, copies outside passes, balanced debug groups, `k*` limits) are asserted where they are broken. Backends walk the stream with `commands()` and read payloads and trailing arrays in place (`<teserra/rhi/commands.hpp>`); `describeCommands()` prints it.
- `teserra::test::AllocationCounter` (`<teserra/test/allocation_counter.hpp>`): test executables count heap allocations per thread, for steady-state allocation tests.
- OpenGL 4.5 backend `teserra_rhi_opengl` (layer 3, option `TESERRA_RHI_OPENGL`, default `ON`): `rhi::opengl::backendFactory()` creates a device on a window's OpenGL context. It loads GL with a vendored glad 2 loader (MX mode: no global function pointers), rejects contexts below 4.5 and insufficient limits with an `Error`, fills `DeviceLimits` from the driver, sets `glClipControl(GL_UPPER_LEFT, GL_ZERO_TO_ONE)`, and with `enableBackendDebug` logs `KHR_debug` messages in category `Rhi` at levels mapped from their severity and type. Resources, the swapchain and command replay follow in later issues. The project now enables C for glad, and header checks reject OpenGL headers in public headers.
- First output through the RHI: the OpenGL swapchain renders into an internal image of the framebuffer size (stored top row first) and presents it with a vertically flipped blit and `swapBuffers()`; resizing replaces the image with a new handle, a minimized window has none. The backend replays render passes (clear, `DontCare` invalidation, cached framebuffers), viewport, scissor and debug groups at `submit()`; clears are linear and encoded for sRGB targets.
- `engine::App` owns an `rhi::Device` (`AppConfig::backend`, default OpenGL) and presents through its swapchain: `AppCallbacks::render(App&, rhi::CommandList&)` records into `App::backbuffer()`, the App clears to black without it, skips minimized frames and resizes the swapchain on `WindowResized`. `App::device()` gives access to the device.
- `teserra_add_module(... OPTIONAL_DEPENDS <module>...)`: modules an option may leave out are linked and layer-checked when they exist, with `TESERRA_HAS_<MODULE>` telling the sources; `check_layers.py` reads them as dependencies.
- `teserra_rhi_clear` example: clears the window to a color cycling over time using only RHI calls; smoke run `--frames 60 --hidden-window`.
- Null backend `teserra_rhi_null` (always built): `rhi::null::createHeadlessDevice()` and `rhi::null::backendFactory()` give a `Device` without a GPU. Resources live in handle pools with copies of their descriptors (`buffer(handle)`, `texture(handle)`, ...), a window gives it a swapchain of the window's size, and the command lists submitted in the last frame stay inspectable (`submitted()`). With `enableValidation`, submitted streams are checked against its objects: handle liveness, usages, pipeline formats against the render pass, copy ranges. `engine::App` offers it as `rhi::Backend::Null`, which renders headlessly.
- Descriptor validation for every backend, `<teserra/rhi/validation.hpp>`: buffer, texture, sampler, shader module and graphics pipeline descriptors are checked at creation (sizes, usages, formats, mip levels, vertex layouts, render targets).
- RHI buffers: `Device::writeBuffer()` copies into `GpuOnly` buffers with `CopyDst` usage, ordered between submissions, and `Device::map()` returns the persistent mapping of `Upload` and `Readback` buffers. Both are validated (`validateWriteBuffer()`, `validateMapBuffer()`). The OpenGL backend creates buffers with immutable storage, persistently and coherently mapped where the CPU accesses them, replays `copyBuffer`, and reports `OutOfMemory`; the null backend keeps buffer memory for tests (`NullDevice::bufferData()`).
- Command stream validation for every backend: `rhi::validateCommands(list, objects)` checks a submitted list against a device's objects through `rhi::ResourceLookup`. The null and OpenGL backends call it in `submit()` with `enableValidation`; the OpenGL backend now validates before any GL call.
- RHI shader modules in the OpenGL backend: GLSL is compiled per stage, and a failed compile returns `ErrorCode::CompilationFailed` with the debug name, the stage and the driver's log with its line numbers, logged at Error. Until `.tshader` blobs exist, `rhi::temporaryGlslBlob()` wraps GLSL 450 source in a shader blob (temporary, removed by #44).
- Graphics pipelines in the OpenGL backend: programs linked once per shader pair and shared, a vertex array per pipeline from its vertex layout (float, normalized and integer formats, per-instance buffers), and fixed-function state captured as GL values. A backend state cache applies only the state that differs, so binding the same pipeline again costs no GL call. Link failures return `CompilationFailed` with the driver's log. The shared validation checks pipeline formats against the render pass on OpenGL too.
- Draws in the OpenGL backend: vertex and index buffer bindings, applied to the bound pipeline's vertex array at the next draw, and `draw` / `drawIndexed` with instances, first instance and vertex offset. The shared validation reports draws whose pipeline has an unbound vertex buffer slot. A GPU test confirms that counter-clockwise triangles are front faces and that row 0 is the top.
- `teserra_rhi_triangle` example: an indexed, vertex-colored triangle from RHI buffers, shaders and a pipeline with back-face culling; it also logs to `teserra.log`. Smoke run `--frames 120 --hidden-window`.
- `teserra_shaderc` (`tools/shaderc/`), the build-time shader compiler of ADR-0017: compiles GLSL 450 (Vulkan dialect) to SPIR-V 1.5 for Vulkan 1.2 with glslang, reflects it and emits GLSL 450 core for OpenGL with flat bindings using SPIRV-Cross, and writes a `.tshader` blob (glslang and SPIRV-Cross are new required vcpkg dependencies, linked statically into the tool only). Resources the RHI cannot bind (sets above 3, bindings above 7, duplicate bindings, arrays, separate samplers, storage images, push constants, matrix vertex inputs) are errors. The stage comes from the extension (`.vert`, `.frag`, `.comp`); `#include "x"` resolves next to the including file and then in `-I` directories, `#include <x>` in `-I` directories, without an `#extension` line; shaders see `TESERRA_SHADER`, a `TESERRA_STAGE_*` macro and `-D` macros. Errors, also in included files, are printed as `file(line): error: message` (`--diagnostics msvc`, the Windows default) or `file:line: error: message` (`gcc`) with exit code 1; usage and I/O errors exit with 2, and a failed compile removes the output file. Option `TESERRA_SHADER_VALIDATION` (vcpkg feature `shader-validation`, on in `ci-windows`) validates the output in the tests with SPIRV-Tools, the checks of `spirv-val`.
- `.tshader` blobs, `<teserra/rhi/shader_blob.hpp>`: `writeShaderBlob()` and `readShaderBlob()` (views into the blob; `InvalidData` for malformed or truncated blobs, `Unsupported` for another format version) for a stage's SPIR-V, GLSL for OpenGL and `ShaderReflection` (bindings with group, binding, `BindingType`, size and name; vertex inputs with location, scalar type and components). `rhi::flatBinding(group, binding)` (`group * 8 + binding`) is the OpenGL binding index that the emitted GLSL uses. `<teserra/rhi/binding.hpp>` defines `BindingType` (`UniformBuffer`, `StorageBuffer`, `SampledTexture`); `ShaderStage::Compute` marks compute shader blobs (no compute pipelines yet).
- `teserra_add_shaders(<target> SOURCES ... [EMBED [NAMESPACE] [HEADER]] [OUTPUT_DIRECTORY] [INCLUDE_DIRECTORIES] [DEFINES])` (`cmake/TeserraShaders.cmake`): compiles shaders with `teserra_shaderc` as part of building a target, recompiling a shader only when it, an included file or the tool changes. Shader errors fail the build with the tool's message. Without `EMBED` the blobs are files; with `EMBED` they are compiled into the target and declared in a generated header as `extern const std::span<const std::byte> k<FileName>` (4-byte aligned). `teserra_shaderc --depfile <file>` writes the dependency file it uses.
- `tools/scripts/package_example.py`: zips an example of a Release build for testers, with its DLLs, the Visual C++ runtime, `LICENSE`, `THIRD_PARTY_NOTICES.md` and a `README.txt` from `tools/packaging/README.txt.in`. `THIRD_PARTY_NOTICES.md` lists the dependencies in the binaries.
- RHI bind groups (`<teserra/rhi/binding.hpp>`): `BindGroupLayoutDesc` (entries with binding, type, stage visibility and dynamic offset), `PipelineLayoutDesc` (up to 4 groups by set, null for an empty set) and `BindGroupDesc` (buffer ranges; texture and sampler slots for iteration 7), with `Device::createBindGroupLayout` / `createPipelineLayout` / `createBindGroup` and `destroy()`. Set indices by frequency: `kFrameGroup`, `kPassGroup`, `kMaterialGroup`, `kDrawGroup`. Creation copies what it needs from the layouts it names, so a layout may be destroyed while objects made from it live. `DeviceLimits` reports `maxBindGroups` (4) and `maxBindingsPerGroup` (8).
- Bind group validation shared by every backend: `validateBindGroupLayoutDesc`, `validatePipelineLayoutDesc` and `validateBindGroupDesc` at creation; `validateGraphicsPipelineResources` checks every resource in a shader's `.tshader` reflection against the pipeline layout (present, same type, visible to the stage); `validateCommands` checks that a draw has a bind group with an equal layout at every set of the pipeline's layout, that `bindGroup` passes one dynamic offset per dynamic binding, and that a group's resources are alive. `ResourceLookup` gains `sampler()`, `shaderModule()`, `bindGroupLayout()`, `pipelineLayout()`, `bindGroup()` and `graphicsPipelineLayout()`. The null backend keeps the objects for inspection; the OpenGL backend keeps their descriptors and binds groups with #43.
- Bind groups in the OpenGL backend: replaying `bindGroup` binds each uniform buffer with `glBindBufferRange` at `rhi::flatBinding(set, binding)`, with its dynamic offsets added. Layouts with storage buffers return `ErrorCode::Unsupported` until #190. The leak check keeps `flatBinding` inside `shader_blob.hpp`, the OpenGL backend and `tools/shaderc` (rule `flat-binding-leak`).
- Offset validation for bind groups: uniform buffer ranges start at a multiple of `DeviceLimits::uniformBufferOffsetAlignment` and see at most `maxUniformBufferRange` bytes, and every dynamic offset is aligned and keeps its binding's window inside the buffer.
- `teserra_assets` (layer 2) with image decoding, `<teserra/assets/image.hpp>`: `assets::decodeImage(bytes, config)` decodes a PNG file in memory into `ImageData` (width, height, `ImageFormat::Rgba8`, tightly packed pixels with row 0 as the top row of the file). Grayscale, RGB, palette and 16-bit images are converted to RGBA8. `ImageDecodeConfig` limits the size per side (default 16384) and the decoded size (default 256 MiB), checked against the header before anything is allocated (`Unsupported`); empty, malformed and truncated data is `InvalidData`. stb_image (vcpkg `stb`) is a private dependency, compiled for PNG only, and the header checks also reject it in public headers.
- Textures: `Device::writeTexture(texture, region, bytes, bytesPerRow)` uploads a `TextureRegion` (mip level, layers, top-left texel and size) with rows top row first and layers one after another, and `Device::generateMipmaps(texture)` fills the mip chain from level 0, filtering sRGB textures in linear space. `mipLevelCount()` resolves `kAllMips` and `textureDataSize()` gives the bytes an upload reads. The format support table `FormatInfo::capabilities` (`FormatCapabilities`: sampled, filterable, render target, blendable, depth-stencil, storage) holds what OpenGL 4.5 and core Vulkan both guarantee, and validation checks texture usages, pipeline color targets and blending against it; `validateWriteTexture`, `validateGenerateMipmaps` and `validateTextureRegion` (also used for copy commands, which now check the mip level) are the new checks. The OpenGL backend creates 2D and 2D-array textures with immutable storage, uploads with `glTextureSubImage*` without a flip (BGRA formats upload into RGBA storage), replays `copyBufferToTexture`, generates mips with `glGenerateTextureMipmap`, and attaches depth-stencil textures and array layers in render passes, with depth and stencil clears; 3D, cube and multisampled textures are `Unsupported` in v1. The null backend keeps uploaded texels per mip level (`NullDevice::textureData()`).
- File system service `<teserra/platform/file_system.hpp>`: `platform::FileSystem` with `readFile`, `writeFile`, `exists`, `executableDirectory` and `userDataDirectory(appName)` (`%APPDATA%\<appName>` on Windows, created if missing), implemented by `NativeFileSystem` and returned by the new `Platform::fileSystem()`. Paths are UTF-8 strings on every OS, and returned directories use `/`. `writeFile` writes a temporary file and renames it over the target, so a crash keeps the previous content. Errors name the path: `NotFound`, `AccessDenied`, `InvalidArgument` (empty path, invalid UTF-8, a directory) or `IoFailure`.
- Samplers in the OpenGL backend: `createSampler` makes a GL sampler object from every field of `SamplerDesc` (filters, mip filtering, address modes, comparison, anisotropy clamped to the driver's limit and only with `EXT_texture_filter_anisotropic`), and replaying `bindGroup` binds each `SampledTexture` binding's texture and sampler to the texture unit at `rhi::flatBinding(set, binding)`.
- Bind group validation: a sampler that filters linearly (min or mag filter, or mipmaps of a texture with several levels) needs a texture format with `FormatCapabilities::Filterable`, as on Vulkan.
- `teserra_textured_quad` example: a PNG read with `platform::FileSystem` and `assets::decodeImage()` is uploaded to an sRGB texture and drawn on a square quad through a bind group at the material set; Space switches between nearest and linear filtering, shown in the window title. Smoke run `--frames 120 --hidden-window`.
- Readback in the OpenGL backend: `copyTextureToBuffer` writes a texture region into a buffer, top row first, through a pixel pack buffer.
- GPU convention tests that use RHI calls only and read results back through a `Readback` buffer: a texture is rendered (row 0 is the top, counter-clockwise faces are front faces), sampled into another texture in the next pass without a barrier call, and read back. The swapchain image is checked the same way before `present()`. The presented window is a documented visual check (`teserra_textured_quad`).
- Frames in flight: `Device::frameSlot()` gives the current frame's slot (frame N uses slot N % `kMaxFramesInFlight`) for per-frame resources. The OpenGL backend places a fence per slot at `endFrame()` and waits on it in `beginFrame()` before reusing the slot; `waitIdle()` drains them. The null backend models fences: frame N completes when frame N + 2 begins or at `waitIdle()`, and destroyed objects are kept until the frames that may use them have completed (`NullDevice::pendingDestructionCount()`, `completedFrameCount()`), the rule a Vulkan backend follows.
- `teserra_renderer` (layer 3, depends on core, rhi and assets) with the frame structure: `Renderer::create(device, config)`, `addPass()` and `render(packet, target, commands)`, which records into the App's command list; `FramePacket` with a list of `RenderView`s (camera, clear color, order); `CameraData`, the std140 camera block at set 0; `UploadRing`, per-frame-slot upload memory with aligned sub-allocation that asserts on writes that could reach data in flight; and `RenderPass` with `declare()` / `execute()`, `PassBuilder`, `PassContext` (views, uploads, declared targets, `bindView()`), each pass in a debug group. A steady-state frame allocates nothing.

Engine shaders include the matching camera block from `teserra/camera.glsl`.

It allocates nothing in steady state.
- `SpritePass` (`<teserra/renderer/sprite_pass.hpp>`): draws `FramePacket::sprites` with the built-in `sprite_unlit` material (texture × tint, alpha / premultiplied / additive blending) in one draw call per batch, for every view (viewport and scissor from the new `RenderView::viewport`); pipelines and per-texture bind groups are created on first use and kept, so steady-state frames create nothing and allocate nothing. `PassContext::packet()` gives passes the frame's render data.

In debug builds, two paths with the same hash, one path as two types and an asset loading itself assert.

Empty, `.` and `..` components and `:` after the scheme are rejected with an `Error`, so a path cannot leave its mount and each file has one spelling. `engine::App::mounts()` mounts `assets://` to `<executable dir>/assets` and `engine://` to `<executable dir>/engine` unless `AppConfig::mounts` lists them; listed directories may be relative to the executable's directory and must exist. Test helper `teserra::test::writePng()`.

- Sprite sheets: `renderer::SpriteSheet` names regions of a texture asset (in texels, top-left origin; `regionUv()`), from a list or a grid (`SpriteSheet::grid()` with cell size, margin, spacing, count and name prefix), with world sizes from `pixelsPerUnit` (default 16). A sheet of a fallback texture shows the whole fallback in every region. `scene::spriteFromSheet()` makes a `SpriteRenderer` for a region. `renderer::UvRect` is comparable. The `scene_sprites` example draws its grass, hero and coins from `assets://sprites.png`.
- Tilemap data in `teserra_scene`: the `Tilemap` component (`<teserra/scene/tilemap.hpp>`, portable) holds a tile size and named `TilemapLayer`s of `TileId`s (0 is no tile, n is tile n - 1 of the tileset) on integer coordinates, also negative, stored sparsely in 32x32 `TilemapChunk`s (`chunkOf()`, floor division); an edit marks only its chunk dirty, and `kNoTile` never allocates. `scene::Tileset` (`<teserra/scene/tileset.hpp>`, with the renderer) maps tile ids to sprite sheet regions (`Tileset::grid()`, `uv()`) and `TileProperties` (`solid`), with defaults for tiles without properties.
- Tile queries for gameplay (`<teserra/scene/tile_queries.hpp>`): `scene::TilemapQuery` places a `Tilemap` in the world by its entity's matrix and answers `worldToTile()`, `tileCenter()`, `tileBounds()`, `tileAt(layer, worldPos)`, `tileRange(box)` and `tilesOverlapping(layer, box, f)` / `anyOverlapping(layer, box, pred)` (a box overlapping a tile's inside reaches it, touching its edge does not), without allocating; `localToTile()` converts local positions. With the renderer, `isSolidAt()` and `overlapsSolid()` check a `Tileset`'s solid tiles.

The sprite pass draws each chunk with the sprite material before the sprites of its layer, sampled with `SpritePassConfig::tilemapFilter` (nearest by default), with UVs pulled in by 1/64 texel against seams. `RenderExtraction` counts `culledChunks` and `builtChunks`; `SpritePassStats::tilemapChunks` counts the drawn ones. New `teserra_tilemap` example: a 256x256, 3-layer map that scrolls and zooms, with flowers planted under the camera on Space.

Unsupported features (infinite maps, other orientations, base64 or compressed data, flipped tiles, group and image layers, non-rectangle objects, TSX tilesets) are `Unsupported` errors, and broken data is `InvalidData`, both naming the layer and tile or object. `scene::tilemapFromTiled()`, `tilesetFromTiled()` (a tile's `solid` property) and `tiledObjectBounds()` bring a map into a scene, +Y up.

Unknown keys are one warning; a malformed sidecar fails the load with its path. `TextureLoader` makes `Rgba8Unorm` textures for `"srgb": false` and generates a full mip chain for `"mipmaps": true`.

The transform system propagates full 3D matrices top-down by depth (any storage order, up to `kMaxHierarchyDepth` levels; cycles assert) and destroys the subtree of a destroyed parent through commands. - Events (`<teserra/ecs/events.hpp>`): `ecs::Events<T>` resources, double-buffered so events sent in frame N are readable in N and N+1, with `EventCursor`s so every reader sees each event once. `addEvents<T>(world)` / `Scene::addEvents<T>()` register a type and `updateEvents(world)` swaps them all; scenes do it at the start of PreUpdate. - Collision (`<teserra/scene/collision.hpp>`): `scene::Collider` boxes; `moveAgainstTiles()` moves a box against solid tiles axis by axis with swept checks, so nothing tunnels; the collision system (PostUpdate, after the transforms) sends `CollisionStarted` / `CollisionEnded` events when colliders start and stop overlapping, with the pairs in the `CollisionState` resource; and `CollisionDebug` outlines colliders in debug draw.

- Render targets (`<teserra/renderer/render_target.hpp>`): the renderer draws the scene into its own target, color plus a `Depth32Float` depth attachment, and its built-in composite pass (always the last pass) draws that target into the frame's output. `RendererConfig::scene` (`AppConfig::sceneTarget` in the App) either matches the output or fixes a resolution, such as 320x180, which is scaled by the largest whole factor that fits and letterboxed (`compositeRect()`, `outputToScene()` for mouse input). Resizing recreates the target; the device destroys the old one after the frames in flight. Cameras render into targets of their own with `Camera::target` (`Renderer::createRenderTarget()`), which sprites can then show, for minimaps; a sprite is never drawn into the target it shows. `App::renderer()` gives games the App's renderer, and `AppConfig::spritePass` its sprite filter. The `pixel_perfect` example renders at 320x180 with a camera that follows a child of the hero and a minimap.

- Materials (`<teserra/renderer/material.hpp>`): `Material` (a vertex and a fragment `Shader` asset, `MaterialState` with blend mode, depth test and write and cull mode, and a parameter layout built from the shaders' reflection of set 2) and `MaterialInstance` (parameter values set by name and type, textures, a uniform buffer and the bind group of set 2). `MaterialLoader` and `MaterialInstanceLoader` read `*.material.json` and `*.material-instance.json`. `.tshader` blobs now reflect the members of uniform blocks (a new block member section that older readers skip), and `Shader` assets keep their reflection. Sprites draw with a material instance through `SpriteDrawItem::material` / `scene::SpriteRenderer::material`: parameters at set 2, the sprite's texture at set 3, pipelines from the new `PipelineCache`, created once and logged at Debug.

### Changed

- Pipeline validation checks the vertex shader's inputs against the vertex attributes (#188): an input without an attribute at its location, an integer input fed by a float or normalized attribute (or the reverse), or an attribute with fewer components than the input now fails `createGraphicsPipeline()` with validation on.
- Draw validation checks that each uniform buffer range a bind group binds covers the block the pipeline's shaders read there (#191): a shorter range now fails `submit()` with validation on, naming the block, its set and binding, and both sizes. `PipelineLayoutInfo` and `StoredPipelineLayout` gain `uniformBlocks`, which backends fill with the new `uniformBlocksOf()` at pipeline creation.
- Passes draw into the scene target instead of the frame's output: `PassResource::SceneColor` is the scene target (`FrameTarget` gains `depthTexture`, `depthFormat` and `layout()`), `PassResource::Output` is the frame's output, and `PassContext::viewTarget()` gives each view's target. The sprite and debug passes start one render pass per run of views with the same target, and key their pipelines by the target's layout. `RenderExtraction::targetSize` is the scene target's size; `RenderExtraction::renderer` sizes the views of cameras with targets.

- Shader modules take only `.tshader` blobs, on every backend: the temporary GLSL path (`rhi::temporaryGlslBlob()`, `rhi::temporaryGlslSource()`) is removed. The new `rhi::readShaderModuleBlob()` reads a module's blob for the backends. The null backend now refuses other blobs, as OpenGL does: `InvalidData` with the module name, or `InvalidArgument` for a blob of another stage. The OpenGL GPU tests compile their shaders with `teserra_add_shaders()`.
- `rhi::validateBindGroupDesc()` and `rhi::validateCommands()` take the device's `DeviceLimits` as a last parameter. Only backends call them.
- Copy commands refuse depth textures in both directions; readback of depth textures was never implemented.
- `rhi_triangle` turns: its vertex shader reads the angle from a per-frame uniform buffer at set 0, bound with a dynamic offset into one slot per frame in flight.
- The OpenGL backend compiles the GLSL of `.tshader` blobs; `rhi_triangle` draws with shaders compiled at build time and embedded by `teserra_add_shaders()` (`examples/rhi_triangle/shaders/`). Blobs that are neither `.tshader` nor temporary GLSL now fail with `InvalidData` instead of `Unsupported`.
- `teserra_engine` declares `core` in `DEPENDS`, which it includes directly.
- `AppConfig::graphicsApi` is replaced by `AppConfig::backend` (`std::optional<rhi::Backend>`; `std::nullopt` for an App without a device). `vsync` selects the swapchain's present mode.
- Descriptor and config structs give every field a default, so they can be created with partial designated initializers without Clang warnings: `App app{{.title = "Game", .args = {argc, argv}}}`, `app.run({.update = ...})`. `AppCallbacks` members and `LogConfig::filePath` gained `{}` defaults; the `window_input` example and the App tests use the style.
- The repository is now `fyernald/teserra` (clone with `git clone https://github.com/fyernald/teserra.git`); links are updated and old `fyernald/tessera` URLs redirect. The project name stays Teserra.

### Fixed

- `gl_InstanceIndex` counts from the draw's first instance on OpenGL drivers without `GL_ARB_shader_draw_parameters` too (#185): the backend sets SPIRV-Cross's `SPIRV_Cross_BaseInstance` uniform before draws, where it stayed 0.
- A window resized by dragging its border on Windows is drawn at every size it passes through (#184): the window system's resize loop kept `pollEvents()` from returning, so the window showed its last frame cut off at the new size until the mouse button was released. The platform now calls a live-resize handler (`Platform::setLiveResizeHandler()`) from inside the poll, and the App finishes a frame there for each new size.
- Log calls removed by `TESERRA_LOG_LEVEL_MIN` (Trace and Debug in Release) have their format string checked with GCC too; GCC does not evaluate the `consteval` check in a discarded `if constexpr` branch, so a wrong format string compiled there (#68).
- `teserra_add_shaders()` works in deep build directories on Windows (#192): generated blobs and sources moved from `generated/teserra_shaders/<target>/blobs/` and `.../src/` to `tsh/<hash of the target>/`, which saves about 45 characters, and a generated path that Windows could not write (260 characters or more) now fails configuration with a message that names it, instead of failing the build.
- `tools/scripts/package_example.py` includes the example's `assets/` folder, so a packaged `textured_quad` finds its image, and its README describes what `textured_quad` testers should see.
