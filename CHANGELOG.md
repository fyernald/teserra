# Changelog

All notable user-visible changes to Teserra are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Policy: [release process](docs/process/release-process.md#changelog-policy).

## [Unreleased]

### Added

- Project documentation: architecture, ADRs, coding standards, pattern catalog, build/CI and testing strategy, development and release process.
- Contributor guide, Code of Conduct, security policy, issue and pull request templates.
- CMake build skeleton: `teserra_add_module()` with a configure-time layer check, per-compiler warning flags, `teserra_core` with `<teserra/core/config.hpp>`, `<teserra/core/types.hpp>` and a generated `<teserra/core/version.hpp>`, and the `teserra_hello` example.
- One-command build: `CMakePresets.json` (Windows MSVC/clang-cl, CI, prepared Linux presets) and vcpkg manifest mode with a pinned baseline (`cmake --workflow --preset windows-msvc-debug`).
- Catch2 v3 test integration: `teserra_add_test()` registers each test case with CTest; `teserra_core_tests`; JUnit report from the `ci-windows` test preset.
- GitHub Actions CI: `windows-msvc` job (build and tests with test annotations and a cached vcpkg) on every push to `main` and every pull request; CI badge in the README.
- `.clang-format` and `.clang-tidy` (naming rules of ADR-0021), `format` / `format-check` / `check` targets and the CI `checks` job.
- Logging facade `<teserra/core/log.hpp>`: `TESERRA_LOG_{TRACE,DEBUG,INFO,WARN,ERROR,CRITICAL}(category, format, args...)` with compile-time checked `std::format` strings and source locations, engine categories plus `log::registerCategory()` for games, a compile-time floor `TESERRA_LOG_LEVEL_MIN`, runtime levels per category, colored console and rotating file output (`log::configure()`), and `log::CallbackSink` to capture messages. spdlog is a private dependency of `teserra_core`.
- Profiling macros `<teserra/core/profile.hpp>` (`TESERRA_PROFILE_SCOPE`, `_FUNCTION`, `_FRAME_MARK`, `_ALLOC`, `_FREE`, `_THREAD_NAME`); no-ops until the Tracy integration.
- Test helpers `teserra_add_header_check()` (every public header compiles on its own and keeps spdlog/fmt private) and `teserra_add_compile_fail_test()`.
- Assertions `<teserra/core/assert.hpp>`: `TESERRA_ASSERT`, `TESERRA_VERIFY`, `TESERRA_UNREACHABLE` and `TESERRA_FATAL` with optional `std::format` messages. Failures are logged at Critical with the caller's location and flushed; the default handler breaks into an attached debugger and aborts, and `setAssertHandler()` replaces it. CMake option `TESERRA_ENABLE_ASSERTS` (`DEFAULT`: Debug and RelWithDebInfo, `ON`, `OFF`).
- `Result<T>` and `Error` (`<teserra/core/result.hpp>`): `Result<T>` aliases `tl::expected<T, Error>` (a public dependency of `teserra_core`); `Error` holds an `ErrorCode`, the `Module` that failed and a message, and formats as `"<message> (<module>, <code>)"`; `fail()` creates errors; `TESERRA_TRY` and `TESERRA_TRY_ASSIGN` propagate them. Discarding a `Result` is diagnosed. `log::configure()` now returns `Result<void>` and leaves logging a failure to the caller.
- Math `<teserra/core/math.hpp>` over glm (a public dependency of `teserra_core`): `Vec2/3/4`, `IVec2`, `UVec2`, `Mat3`, `Mat4`, `Quat`, `Color`, `Rect`, 3D `Aabb`, and `teserra::math` functions (`dot`, `cross`, `length`, `normalize`, `lerp`, `radians`, `perspective`, `orthographic`, `lookAt`, `inverse`, `angleAxis`, `toMat4`, box helpers). glm is configured once with `GLM_FORCE_DEPTH_ZERO_TO_ONE` and `GLM_FORCE_RADIANS`; projections are right-handed with depth `[0, 1]` and +Y up.
- Generational handles: `Handle<Tag>` (`<teserra/core/handle.hpp>`: 32-bit index + 32-bit generation behind accessors, null by default, distinct types per tag, comparable, hashable, formattable) and `HandlePool<T, Tag>` (`<teserra/core/handle_pool.hpp>`: slot array with per-slot generations, FIFO slot reuse, retirement at the maximum generation, asserting `get()`, `tryGet()` returning `nullptr` for stale handles, `forEach()` over live objects).
- `teserra_core_sandbox` example: logging in several categories, a recoverable `Result` error handled with a fallback, handles and math; `--assert` shows a failed `TESERRA_ASSERT` with file and line in Debug. It runs as a CTest smoke test that fails on Error-level output.
- Platform layer `teserra_platform` (layer 1) with a GLFW backend (`TESERRA_WINDOW_BACKEND`, PRIVATE GLFW 3.4): `platform::Platform::create()`, `Window` (sizes, content scale, `setSize`, `setTitle`, close and focus state, `NativeWindowHandle`), `OpenGlContext` for OpenGL 4.5 core contexts, and an `EventQueue` with `WindowResized`, `WindowCloseRequested` and `FocusChanged` events. Window functions assert they run on the main thread. The header checks also reject GLFW and `<windows.h>` in public headers.
- Keyboard and mouse input in `teserra_platform`: `platform::Key` (physical keys with US-layout names) and `MouseButton` with `keyName()` / `mouseButtonName()`; `KeyChanged`, `MouseButtonChanged`, `MouseMoved`, `MouseScrolled` and `TextEntered` events from the GLFW backend; and `platform::Input`, built from those events each frame, with `isDown` / `wasPressed` / `wasReleased` for keys and buttons, mouse position and delta, scroll, typed text (UTF-8) and `axis2D()`. Losing focus releases held keys and buttons.
- Timing in `teserra_platform`, using only `std::chrono`: `platform::Clock` (monotonic `now()` in nanoseconds) with `SteadyClock` and a `ManualClock` for tests; `Platform::clock()`; `FrameTimer` (delta, elapsed time, frame count, FPS averaged over 500 ms windows); and `FixedStepAccumulator` (fixed steps, default 60 Hz, with the remainder carried over and at most `maxStepsPerFrame` steps after a stall, reporting the dropped ones).
- `teserra_engine` (layer 6) with `engine::App`: owns the platform and the window (created in dependency order, destroyed in reverse), runs the frame (events and `Input`, fixed steps, update, present with vsync) with `AppCallbacks` until `quit(exitCode)`, a close request or `AppConfig::maxFrames`, and returns the exit code from `run()`. Initialization failures are logged and make `run()` return 1. The engine flags `--frames N` and `--hidden-window` are read from `AppConfig::args`. An injected `platform::Platform` lets tests run it headless.
- `teserra_window_input` example: logs keyboard, mouse and text input, shows FPS, the cursor and a WASD-moved position in the title, and quits on Escape or close; its CTest smoke run (`--frames 120 --hidden-window`) is skipped on machines without OpenGL 4.5.
- Shared test support for all test executables (`tests/support/`): failed assertions fail the current test instead of aborting, `REQUIRE_ASSERTS(expr)` / `teserra::test::requireAssert()`, `teserra::test::LogCapture`; `teserra_add_abort_test()` for behavior that ends the process.
- Layer and leak checks: `tools/scripts/check_layers.py` (a module includes only its own headers and those of its direct `DEPENDS`) and `tools/scripts/check_gl_leaks.py` (GL, Vulkan, GLFW, Win32 and glm names stay in their backend or module; `TODO(#issue)`), with unit tests, `layer-check` / `leak-check` targets in `check`, and steps with pull request annotations in the CI `checks` job.
- `teserra_rhi` (layer 2), the public RHI types: handles, `Format` / `VertexFormat` with `formatInfo()` / `vertexFormatInfo()`, API bounds (`kMaxColorAttachments`, ...) and `DeviceLimits`, the descriptors `BufferDesc`, `TextureDesc`, `SamplerDesc`, `ShaderModuleDesc`, `GraphicsPipelineDesc` (all fixed-function state) and `RenderPassDesc` (trivially copyable, load/store ops), the `Device` and `Swapchain` interfaces, and `createDevice()`, which picks among the backend factories the build passes in. No backend yet.
- `<teserra/core/flags.hpp>`: `TESERRA_FLAGS(Enum)` gives scoped flag enums `| & ^ ~`, compound assignment, `hasAll()` and `hasAny()`.
- `rhi::CommandList` (`<teserra/rhi/command_list.hpp>`): records render passes, bindings (pipeline, bind groups with dynamic offsets, vertex and index buffers), viewport and scissor, draws, buffer and texture copies, and debug groups as POD records in a reused byte stream, without backend calls or, after warm-up, heap allocations. Recording rules (no nested passes, draws need a pass and a pipeline, each pass starts with nothing bound, copies outside passes, balanced debug groups, `k*` limits) are asserted where they are broken. Backends walk the stream with `commands()` and read payloads and trailing arrays in place (`<teserra/rhi/commands.hpp>`); `describeCommands()` prints it.
- `teserra::test::AllocationCounter` (`<teserra/test/allocation_counter.hpp>`): test executables count heap allocations per thread, for steady-state allocation tests.
- OpenGL 4.5 backend `teserra_rhi_opengl` (layer 3, option `TESERRA_RHI_OPENGL`, default `ON`): `rhi::opengl::backendFactory()` creates a device on a window's OpenGL context. It loads GL with a vendored glad 2 loader (MX mode: no global function pointers), rejects contexts below 4.5 and insufficient limits with an `Error`, fills `DeviceLimits` from the driver, sets `glClipControl(GL_UPPER_LEFT, GL_ZERO_TO_ONE)`, and with `enableBackendDebug` logs `KHR_debug` messages in category `Rhi` at levels mapped from their severity and type. Resources, the swapchain and command replay follow in later issues. The project now enables C for glad, and header checks reject OpenGL headers in public headers.
- First output through the RHI: the OpenGL swapchain renders into an internal image of the framebuffer size (stored top row first) and presents it with a vertically flipped blit and `swapBuffers()`; resizing replaces the image with a new handle, a minimized window has none. The backend replays render passes (clear, `DontCare` invalidation, cached framebuffers), viewport, scissor and debug groups at `submit()`; clears are linear and encoded for sRGB targets.
- `engine::App` owns an `rhi::Device` (`AppConfig::backend`, default OpenGL) and presents through its swapchain: `AppCallbacks::render(App&, rhi::CommandList&)` records into `App::backbuffer()`, the App clears to black without it, skips minimized frames and resizes the swapchain on `WindowResized`. `App::device()` gives access to the device.
- `teserra_add_module(... OPTIONAL_DEPENDS <module>...)`: modules an option may leave out are linked and layer-checked when they exist, with `TESERRA_HAS_<MODULE>` telling the sources; `check_layers.py` reads them as dependencies.
- `teserra_rhi_clear` example: clears the window to a color cycling over time using only RHI calls; smoke run `--frames 60 --hidden-window`.

### Changed

- `teserra_engine` declares `core` in `DEPENDS`, which it includes directly.
- `AppConfig::graphicsApi` is replaced by `AppConfig::backend` (`std::optional<rhi::Backend>`; `std::nullopt` for an App without a device). `vsync` selects the swapchain's present mode.
- Descriptor and config structs give every field a default, so they can be created with partial designated initializers without Clang warnings: `App app{{.title = "Game", .args = {argc, argv}}}`, `app.run({.update = ...})`. `AppCallbacks` members and `LogConfig::filePath` gained `{}` defaults; the `window_input` example and the App tests use the style.
- The repository is now `fyernald/teserra` (clone with `git clone https://github.com/fyernald/teserra.git`); links are updated and old `fyernald/tessera` URLs redirect. The project name stays Teserra.
